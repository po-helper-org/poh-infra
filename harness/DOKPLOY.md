# Развёртывание харнесса на Dokploy

Один Compose-сервис поднимает весь контур: Temporal, Issue-Agent, PR-Agent и
единственную публичную точку входа. Локальный прогон описан в
[`LOCAL.md`](LOCAL.md) — здесь то же самое, но с постоянным адресом вместо
туннеля.

Постоянный адрес и есть главная причина ехать на стенд. Локально адрес живёт
часы и прописан в трёх местах сразу; на стенде он один раз задаётся доменом и
больше не меняется.

---

## 1. Создать сервис

**Create Service → Compose.**

| Поле | Значение |
|---|---|
| Provider | Git, репозиторий `po-helper-org/poh-infra`, ветка `main` |
| Compose Path | `harness/docker-compose.yml` |
| Compose Type | `docker-compose` — **не** `stack` |

`stack` не поддерживает директиву `build`, а образы обоих агентов собираются из
исходников.

**Билдеру нужно ~4 ГБ памяти.** В образ воркера ставятся Node.js, GitHub CLI и
Claude Code (≈1.6 ГБ), плюс отдельно тянется апстрим-образ pr-agent. На инстансе
с 1 ГБ сборка не пройдёт.

## 2. Домен

**Domains → Add.** Хост — свой, сервис — **`caddy`**, порт — **80**.

Caddy внутри разводит один домен на три пути, и это единственный адрес, который
придётся куда-либо прописывать:

| Путь | Куда |
|---|---|
| `/issue/webhook` | приём вебхуков Issue-Agent |
| `/issue/agent-event` | приём докладов от OpenHands и PR-Agent |
| `/pr/webhook` | приём вебхуков PR-Agent |
| `/temporal/` | Temporal UI |
| `/health` | живость харнесса |

**`/temporal/` закрой basic-auth средствами Dokploy.** Он открыт по умолчанию:
локально это удобно, на постоянном стенде — нет.

## 3. Environment

Вкладка **Environment**, вставить целиком. Готовый блок с подставленными
секретами — в `scratchpad/dokploy-harness-env.txt`; ниже что важно понимать.

**`PUBLIC_URL`** — домен из шага 2. Его же берёт Temporal UI для CORS.

**`AGENT_EVENT_SECRET`** — та же строка, что лежит секретом в каждом
репозитории под контуром. Две стороны одного канала: меняются только парой.
Пусто → `/agent-event` отвечает 503, доклады о PR и ревью не доходят, и задача
остаётся в `in-development` навсегда. Всё остальное при этом работает, поэтому
симптом неотличим от зависшего агента разработки.

**`DRY_RUN=`** — пустое значение, а не `0`. Пустое означает боевой режим;
`0` сервис прочитает как «строка задана» и останется в сухом прогоне.

**`RESEARCH_AUTOSTART=1` и `DEVELOP_AUTOSTART=1`** — замкнутый контур. Это две
парковки основного пути: первая перед аналитикой, вторая перед разработкой.
Выключишь любую — цикл остановится там и будет ждать метку человека.

**`GH_TOKEN`** достаточно вместо GitHub App для Issue-Agent: `github_client`
предпочитает токен, если он задан. PR-Agent так не умеет — ему нужен App
(`PR_APP_*`), и без него половина ревью не поднимется (профиль `pr`).

## 4. Что прописать в GitHub

В каждом репозитории из `WATCHED_REPOS`:

```bash
repo=po-helper-org/poh-demo-checkout
gh secret set ISSUE_AGENT_URL    --repo "$repo" --body "https://<домен>/issue"
gh secret set AGENT_EVENT_SECRET --repo "$repo" --body "<та же строка, что в Environment>"
gh secret set LLM_API_KEY        --repo "$repo" --body "<ключ z.ai>"
```

Вебхук — либо GitHub App с адресом `https://<домен>/issue/webhook`, либо вебхук
репозитория с тем же адресом и секретом `ISSUE_APP_WEBHOOK_SECRET`.

## 5. Проверка

Порядок не случаен: каждый шаг проверяет одно звено, и первый несработавший
показывает, где рвётся.

```bash
D=https://<домен>
curl -fsS "$D/health"                                            # харнесс жив
curl -s -o /dev/null -w '%{http_code}\n' -X POST "$D/issue/webhook"      # 401 = живой приём
curl -s -o /dev/null -w '%{http_code}\n' -X POST "$D/issue/agent-event"  # 401 = секрет задан
```

`503` на третьей строке — самая дорогая ошибка конфигурации: см. выше про
`AGENT_EVENT_SECRET`.

## 6. Только issue-половина

PR-Agent вынесен в профиль `pr` и без второго GitHub App не поднимается. Пока
его нет, Dokploy поднимет Temporal + Issue-Agent + вход, а ревью будет гоняться
в Actions репозитория (`pr-review.yml`) — оно докладывает в цикл тем же
`/agent-event`. Контур замкнут в обоих вариантах.

## Грабли

- **Сборка из git-контекста кэшируется по URL.** После нового коммита в ту же
  ветку Dokploy может собрать прежний код. Ветка не менялась, а образ должен —
  пересобирай с `--no-cache` либо меняй `ISSUE_AGENT_CONTEXT` на конкретный SHA.
- **`docker-compose.full.yml` из `poh-issue-agents` — прежний вариант**, только
  Issue-Agent, без PR-Agent и без общего входа. Если на стенде уже развёрнут он,
  харнесс поднимай отдельным сервисом и переключай домен, а не правь старый:
  так есть куда откатиться.
