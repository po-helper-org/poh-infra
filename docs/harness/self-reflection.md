# Саморефлексия: память харнесса об организации

Опциональный слой, который делает харнесс **вашим**. Без него контур ведёт себя
одинаково везде. С ним — накапливает знание о том, как принято работать именно
здесь, и корректирует по нему решения агентов.

Исходники и подробная документация:
[`po-helper-org/harness-memory-base`](https://github.com/po-helper-org/harness-memory-base).
Развёртывание рядом с контуром: [`memory/`](../../memory).

## Что это даёт

**Правила организации доезжают до агента до того, как он начал работу.**
Не в виде «постарайся хорошо», а конкретными пунктами: как здесь принято писать
код, чего требует архитектура, что уже ломалось, на что смотреть при поставке.

**Итерации перестают быть одноразовыми.** Сейчас контур доводит задачу до
пул-реквеста и забывает всё: следующая задача по тому же репозиторию начинается
с чистого листа. Со слоем каждая итерация оставляет след, а когда факты
созревают — слит ли пул-реквест, дожили ли строки до основной ветки, что сказало
ревью — по нему выносится вердикт и извлекается урок.

**Урок проверяется, а не просто записывается.** У каждого есть сигнал, по
которому видно, устранена причина или нет. Последующие итерации подтверждают
или опровергают его арифметикой, без участия модели.

## Кто из агентов что читает

| Агент | Роль | Что берёт |
|---|---|---|
| Issue-Agent | `issue` | как формулировать требования, как считать приоритет, что уточнять до разработки, как декомпозировать |
| Агент разработки | `develop` | как писать код, требования к архитектуре и результату |
| PR-Agent | `review` | что считать замечанием по существу и как его формулировать |
| Агент поставки | `delivery` | знание о ландшафте, выкладке, эксплуатации |

Каждой роли достаются её правила **плюс** общие. Это и есть персонализация:
один и тот же контур в двух организациях начинает вести себя по-разному.

## Как включить за пять минут

```bash
# 1. Сеть, общая с контуром
docker network create harness-memory-net

# 2. Поднять слой
cd memory
cp .env.example .env
openssl rand -hex 24        # вставить в MEMORY_BASE_TOKEN (только ASCII)
docker compose up -d --build

# 3. Включить в контуре: в harness/.env
#      MEMORY_BASE_URL=http://memory-api:8090
#      MEMORY_BASE_TOKEN=<тот же токен>
cd ../harness
docker compose up -d issue-webhook issue-worker
```

Проверка, что агенты видят слой:

```bash
docker compose exec issue-worker python -c "
import os, urllib.request, json
r = urllib.request.urlopen(os.environ['MEMORY_BASE_URL'] + '/health', timeout=5)
print(json.load(r))"
```

## Что происходит, когда выключено

Ровно ничего. Пустой `MEMORY_BASE_URL` — ни одного сетевого вызова и ни одного
изменения в постановках агентам; на стороне контура это закреплено тестом на
побайтовое совпадение.

Отдельно: **отказ слоя не роняет прогон**. Недоступность, таймаут, любой код
ответа кроме двухсотых дают пустой блок и предупреждение в лог. Агент работает
без правил, задача доходит до пул-реквеста. То же решение, что у интеграции с
индексом кода: опциональный источник обязан деградировать, а не отказывать.

## Где живут правила и кто их меняет

Репозиторий памяти разделён надвое:

```
rules/     правила и принципы   — курирует ЧЕЛОВЕК, меняются только пул-реквестом
memory/    эпизоды и вердикты   — пишет МАШИНА, коммитятся автоматически
```

Разделение несущее, а не косметическое: **машина не должна уметь менять то, чем
её поправляют.** Она предлагает кандидатов в `memory/lessons/` со статусом
`proposed` — такой кандидат никому не подсыпается и ни на что не влияет, пока
человек не перенесёт его в `rules/` пул-реквестом.

Это же отвечает на вопрос «а не начнёт ли оно уводить контур не туда»: между
предложением машины и поведением агентов стоит ревью, и обойти его нельзя.

## Нужен ли отдельный сервер

**Да, но маленький — и только ради чтения правил.**

| Часть | Постоянный процесс | Почему |
|---|---|---|
| отдача правил агентам | **нужен** | агент спрашивает в момент работы и ждать не может |
| приём записи об итерации | **нужен** | приходит в момент завершения работы |
| проход рефлексии | **не нужен** | ждёт созревания фактов днями, запускается расписанием |

Постоянная часть — один контейнер: лимит 256 МБ, фактический расход порядка
50 МБ. На том же хосте вебхук контура занимает 51 МБ, прокси индекса — 55 МБ.

Проход рефлексии — короткоживущий контейнер под профилем `reflect`. Обычный
`up -d` его не поднимает: он отрабатывает и умирает. Долгоживущий процесс,
ждущий созревания неделю, был рассмотрен и отвергнут — он гарантированно
переживает выкладку, и всё, что он держал, теряется молча.

Расписание — обычный `cron` хоста, разведённый по времени с работой агентов:
ключ модели в контуре один, и одновременные потребители выбивают ограничение
частоты.

Подробности, включая вариант **вовсе без сервера**, — в
[`docs/deployment.md`](https://github.com/po-helper-org/harness-memory-base/blob/main/docs/deployment.md)
репозитория слоя.

## Развёртывание на Dokploy

Слой разворачивается отдельным проектом типа Compose из
[`memory/docker-compose.yml`](../../memory/docker-compose.yml).

Три вещи, которые легко упустить:

**Переменные задавать в Environment проекта, а не только в `.env`.** Dokploy
переписывает `.env` при каждом деплое из панели. Переменная, заданная только в
файле, после планового деплоя исчезает, сервис уезжает на умолчание, и выглядит
это как внезапная поломка без причины.

**Домен не открывать.** Слою он не нужен: агенты обращаются по внутренней сети
Docker. Порт объявлен через `expose`, а не `ports`, и Traefik про него не
узнает. Память организации — это её правила, решения и следы работы.

**Пин образа полным SHA.** BuildKit кэширует клон по адресу и после нового
коммита в ту же ветку молча собирает прежний код; короткий SHA он не находит
вовсе.

## Что смотреть после включения

```bash
curl -H "Authorization: Bearer $MEMORY_BASE_TOKEN" http://memory-api:8090/stats
```

| Величина | О чём говорит, когда портится |
|---|---|
| `episodes` | не растёт после прогонов — агенты не пишут записи, проверь `MEMORY_BASE_URL` в контуре |
| `verdict_coverage` | падает — проход рефлексии не отрабатывает |
| `episodes_without_verdict` | растёт без остановки — созревание не наступает, скорее всего не задан `MEMORY_GITHUB_TOKEN` |
| `lessons_by_status` | всё в `proposed` — человек не переносит кандидатов, петля разомкнута |

Последняя строка — не поломка, а норма на старте: пока правил в `rules/` не
прибавляется, слой работает только как канал чтения заготовки.

## Границы

Слой **не** управляет репозиториями, не открывает пул-реквесты в чужом коде, не
запускает агентов и не имеет пользовательского интерфейса. Он отвечает на
вопрос «что здесь принято» и записывает, чем кончилась итерация.

Слой **не** меняет правила сам. Всё, что влияет на поведение агентов, проходит
через пул-реквест и ревью человека.
