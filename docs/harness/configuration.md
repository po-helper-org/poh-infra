# Справочник конфигурации (`.env`)

Полный шаблон с комментариями — [`harness/.env.example`](../../harness/.env.example),
скопируй его в `.env` и заполняй по разделам. Здесь — та же конфигурация, но
собранная в таблицы: что обязательно, что по умолчанию, зачем нужно и что
сломается, если забыть.

Забытая обязательная переменная роняет `docker compose up` **сразу**, на
подстановке значения, а не через десять минут сборки образов. Это осознанное
поведение: половина контура, поднятая с забытым секретом, выглядит рабочей —
и это хуже честного отказа на старте.

> На постоянном стенде (Dokploy) часть переменных живёт **не** в этом файле.
> См. раздел [«Что не в `.env` на стенде»](#что-не-в-env-на-стенде) в конце
> страницы — это касается учётки Temporal UI и это не опечатка.

## 1. Что охраняем

| Переменная | Обязательна | Пример | Назначение |
|---|---|---|---|
| `WATCHED_REPOS` | да | `your-org/your-repo,your-org/*` | Репозитории под контуром. Маска `owner/*` покрывает и репозитории, заведённые позже. **Один список на Issue-Agent и PR-Agent** — разъехавшийся охват означает PR без ревью либо ревью без задачи, и это не сразу заметно. |
| `DEFAULT_REPO` | нет | `your-org/your-repo` | Репозиторий по умолчанию для batch-скриптов (backfill, consolidate). |

## 2. Два GitHub App

Приложения два — и это не дублирование конфигурации, а разведение прав:
Issue-Agent пишет в Issues и читает PR, PR-Agent — наоборот. Общий ключ
означал бы, что утечка одного открывает разом и бэклог, и код.

| Переменная | Обязательна | Назначение |
|---|---|---|
| `ISSUE_APP_ID` | для режима App | ID приложения «Issue-Agent» |
| `ISSUE_APP_PRIVATE_KEY_B64` | для режима App | Приватный ключ App, в base64 (`base64 -w0 app-private-key.pem`) |
| `ISSUE_APP_WEBHOOK_SECRET` | **да** | Секрет подписи вебхука Issue-Agent (`openssl rand -hex 32`) |
| `GH_TOKEN` | нет | PAT вместо App целиком, см. ниже |
| `PR_APP_ID` | для профиля `pr` | ID приложения «PR-Agent» |
| `PR_APP_PRIVATE_KEY_B64` | для профиля `pr` | Приватный ключ PR-Agent, в base64 |
| `PR_APP_WEBHOOK_SECRET` | для профиля `pr` | Секрет подписи вебхука PR-Agent |

Вебхук каждого App смотрит на свой путь одного домена:
Issue-Agent → `<PUBLIC_URL>/issue/webhook`, PR-Agent → `<PUBLIC_URL>/pr/webhook`.

### `GH_TOKEN` — запасной путь без App

`github_client` внутри Issue-Agent предпочитает `GH_TOKEN`, если он задан, —
тогда все три переменные `ISSUE_APP_*` можно оставить пустыми. Удобно для
отладки: не нужно заводить приложение, чтобы проверить остальной контур.
Плата за удобство — в задачах вместо бота действует живой человек-владелец
токена, и в логе воркера об этом будет предупреждение. **PR-Agent так не
умеет** — ему нужен настоящий App, без него профиль `pr` не поднимется вовсе.

Если завёл App — убери `GH_TOKEN` из `.env`. Он не откатывается автоматически:
переменная просто перевешивает App, даже если App настроен верно, и это
единственный источник путаницы «App есть, а действует не от его имени».

## 3. Замок контура

| Переменная | Обязательна | Назначение |
|---|---|---|
| `AGENT_EVENT_SECRET` | **да** | Подпись докладов на `/issue/agent-event` |

Одна строка на обе стороны канала: ей же подписывают доставку PR-Agent и
прогон OpenHands в Actions — она кладётся секретом `AGENT_EVENT_SECRET` в
**каждый** репозиторий из `WATCHED_REPOS`.

**Пустое значение — не «выключено», а «эндпоинт закрыт» (503).** Всё
остальное при этом продолжает работать: задачи уходят в разработку, PR
открываются — и ни один не закрывается, потому что доклад о готовом PR
отвергается на входе. Симптом неотличим от зависшего агента разработки, и
отличить одно от другого можно только curl'ом на `/issue/agent-event` (см.
[«Проверка» в endpoints.md](endpoints.md#проверка-что-всё-разобрано-верно)).

Ротация секрета — **обе стороны одновременно**. Поменял в `.env` харнесса —
в тот же момент обнови во всех репозиториях, иначе доклады начнут
отвергаться прямо посреди работающего цикла.

## 5. Насколько контур автономен

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `DRY_RUN` | нет* | `1` (боевой режим = **пусто**) | Сухой прогон: стадии проходят, в GitHub не пишется ничего |
| `DEVELOP_ENABLED` | нет | пусто = включено | `0` останавливает цикл на `ready-for-dev` — поведение до появления автоматической разработки |
| `RESEARCH_AUTOSTART` | нет | пусто = выключено | `1` — не ждать метку человека перед аналитикой |
| `DEVELOP_AUTOSTART` | нет | пусто = выключено | `1` — не ждать метку `build-me` перед разработкой |
| `DEVELOP_MODE` | нет | `local` | `local` — код пишется одноразовым контейнером на этом же сервере; `dispatch` — прогон уезжает в GitHub Actions репозитория-цели |
| `DEVELOP_TEST_COMMAND` | нет | пусто = шаг пропускается | Команда прогона тестов после агента и до пуша |
| `DEVELOP_MODEL` | нет | `openai/glm-4.6` | Модель агента разработки |
| `DEVELOP_TIMEOUT_SEC` | нет | `2700` | Таймаут одной попытки разработки |
| `DEVELOP_WORKFLOW_FILE` | нет, только `dispatch` | `openhands-resolver.yml` | Имя workflow-файла в репозитории-цели |
| `DEVELOP_REF` | нет, только `dispatch` | `main` | Ветка, на которой запускается workflow |
| `AGENT_TRIGGER_ALLOWLIST` | нет | пусто = разрешено всем | GitHub-логины через запятую, кому доступны дорогие ручные стадии (`run:analyze` и т.п.) |
| `PARK_DECISION_HOURS` | нет | `72` | Дедлайн парковки на решение человека |
| `PARK_CLARIFICATION_HOURS` | нет | `48` | Дедлайн парковки на уточнение |
| `PARK_BUILD_HOURS` | нет | `72` | Дедлайн парковки на сборку |
| `PARK_SIDE_STATE_HOURS` | нет | `168` | Дедлайн боковых состояний |

**`DRY_RUN=` — пустая строка, а не `0`.** Сервис отличает «переменная не
задана» от «переменная задана и равна `0`»: `DRY_RUN=0` он прочитает как
«строка есть», не выключит сухой режим и продолжит молчать в GitHub, думая,
что ты этого и хотел.

**`RESEARCH_AUTOSTART` и `DEVELOP_AUTOSTART` — две независимые парковки.**
Замкнутый контур без единого касания человека требует **обеих** единиц
одновременно; включённая только одна остановит цикл перед второй, и это
можно принять за баг, а не за настройку.

**`AGENT_TRIGGER_ALLOWLIST` не закрывает триаж новых Issue** — иначе Issue от
постороннего просто осталось бы необработанным. Он ограничивает только
запуск дорогих ручных стадий метками, которые стоят токенов.

## 6. Инфраструктура

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `POSTGRES_PASSWORD` | **да** | — | Пароль БД Temporal (`openssl rand -hex 24`) |
| `HARNESS_PORT` | нет | `8080` | Порт харнесса на хосте (без Traefik) |
| `TEMPORAL_UI_PORT` | нет | `8233` | Прямой порт Temporal UI, **только loopback** — см. [endpoints.md](endpoints.md#прямой-порт-temporal-ui) |
| `HARNESS_HOST` | для Traefik/Dokploy | `harness.localhost` | Хост, на который заводятся роутеры Traefik (`web` + `websecure`) |
| `PUBLIC_URL` | нет | `http://localhost:8080` | Адрес, который видят сами сервисы (CORS Temporal UI, сборка адресов вебхуков) |
| `ISSUE_AGENT_CONTEXT` | нет | `…/poh-issue-agents.git#main` | Откуда собирается образ Issue-Agent — git-URL с `#ref` либо локальный путь |
| `PR_AGENT_CONTEXT` | нет | `…/poh-pr-agents.git#main:self-hosted` | Откуда собирается образ PR-Agent |
| `TEMPORAL_SEARCH_ATTRIBUTES` | нет | пусто | Включает единую ленту Temporal от триажа до PR — **только после регистрации атрибутов на кластере**, иначе старт воркфлоу падает |
| `SENTRY_DSN` | нет | пусто = выключен | Пусто — это же и процедура отката |
| `SENTRY_ENVIRONMENT` | нет | `harness` | Тег окружения в Sentry |

### `HARNESS_HOST` vs `PUBLIC_URL`

Один и тот же адрес, названный дважды по разным причинам: `HARNESS_HOST` —
голый хост без схемы, из него Traefik собирает правило `Host(...)`;
`PUBLIC_URL` — полный URL со схемой, его читают сами сервисы для CORS и для
сборки ссылок в комментариях GitHub. Разъехавшись, они дают рабочий вход
снаружи и пустую страницу внутри — браузер режет запросы, которые страница
делает сама к себе, потому что список `TEMPORAL_CORS_ORIGINS` не совпадает с
тем, откуда страница фактически загружена.

### Контекст сборки — ловушка кэша BuildKit

`ISSUE_AGENT_CONTEXT` и `PR_AGENT_CONTEXT` задаются **одной строкой целиком**
— в неё кладут и `https://…git#ветка`, и локальный путь к рабочей копии.
Раздельные переменные «репозиторий + ветка» здесь не годятся: путь с
суффиксом `#ref` перестаёт быть путём.

BuildKit кэширует git-клон по URL. После нового коммита в ту же ветку
`docker compose build` может молча собрать **прежний** код — правка уехала в
`main`, образ «пересобрался» без ошибок, а в контейнере лежит старый файл.
На отладке — указывай локальный путь. На стенде, если ветка не менялась,
пересобирай с `--no-cache`, либо пинуй `#<полный SHA>` вместо `#main`.

## Что не в `.env` на стенде

Одна пара переменных **сознательно не читается из общего `.env`**, хотя
логически относится к разделу 6: учётка Temporal UI.

| Переменная | Где лежит на стенде | Где лежит локально |
|---|---|---|
| `TEMPORAL_UI_USER` | `/etc/poh-harness/temporal-ui-auth.env` (0600) | `harness/caddy.env` (в `.gitignore`) |
| `TEMPORAL_UI_PASSWORD_HASH` | то же | то же |

Причина — Dokploy переписывает `.env` из панели на каждом своём деплое.
Учётка, заведённая через переменные окружения панели, пропадала бы молча
вместе со всем входом при следующем нажатии «Deploy». Отдельный файл вне
рабочей копии переживает любой деплой из панели.

Формат файла:

```bash
TEMPORAL_UI_USER=poh
TEMPORAL_UI_PASSWORD_HASH=$$2a$$14$$…    # доллары УДВОЕНЫ — см. ниже
```

Хэш считается так:

```bash
docker run --rm caddy:2-alpine caddy hash-password --plaintext '<пароль>'
```

**Доллары в результате нужно удвоить.** `docker compose` интерполирует
значения любого env-файла (и `--env-file`, и `env_file:` в сервисе) — bcrypt-
хэш состоит из `$`-сегментов (`$2a$14$…`), и без удвоения он доедет до
контейнера обрезанным на первом же `$`. Симптом — контейнер стартует
нормально, но отвергает верный пароль, и это выглядит как опечатка в пароле,
а не как повреждённый хэш. Проверка после любой правки:

```bash
docker exec <проект>-caddy-1 sh -c 'printenv TEMPORAL_UI_PASSWORD_HASH | wc -c'
# ожидается 61 — 60 символов хэша + перевод строки
```

Без обеих переменных `caddy` не поднимется вовсе — это заложено намеренно:
молча открытый наружу Temporal UI хуже упавшего входа, который сразу видно.
