# Repowise — постоянный индекс кода для агентов контура

Агенты контура — Issue, PR, OpenHands — собирали контекст репозитория заново в
каждом прогоне: клон, `repomix`, чтение файлов. Знание умирало вместе с
прогоном, а единственной формой контекста был плоский XML-дамп, которому нельзя
задать вопрос.

Repowise держит **постоянный индекс**: граф символов, история git и blame,
поиск, оценка риска правки, мёртвый код, страницы вики. Агенты обращаются к нему
вопросами по MCP и получают ответы со ссылками на конкретные места в коде.

Спецификация — `po-helper-org/poh-issue-agents`,
`sa_documentation/FNR/FNR_5/system_requirements.md`. Дизайн и обоснования —
`docs/superpowers/specs/2026-08-19-repowise-mcp-service-design.md`.

## Из чего состоит

| Сервис | Что делает | Виден снаружи |
|---|---|---|
| `repowise-contour-mcp` | MCP-эндпоинт workspace `contour` | нет |
| `repowise-product-mcp` | MCP-эндпоинт workspace `product` | нет |
| `repowise-web` | API и веб-админка (`repowise serve`) | нет |
| `repowise-proxy` | маршрут по workspace, токен, журнал обмена, рендер артефакта | только контуру |
| `indexer` | клонирование, первичная индексация, цикл обновления | нет |
| `caddy` | публичный вход, `basic_auth`, свой домен | да, единственный |

```
агенты контура ──poh-repowise-net──▶ repowise-proxy ──┬─▶ contour-mcp :7338
(аналитика, OpenHands)                журнал сессий   └─▶ product-mcp :7338
                                                            │
                          indexer ─────────────────────────┘
                          (расписание)      том repowise-workspaces

человек ──▶ caddy (basic_auth) ──▶ repowise-web        (свой домен)
```

## Три решения, которые объясняют устройство

**Граница доступа проходит по сети, а не по соглашению.** Порты MCP-эндпоинтов
и веб-интерфейса не публикуются на хост, и Traefik про них не знает. Контуру
виден ровно один сервис — прокси, и тот требует токен. «Только внутренний
контур» — это свойство топологии, а не договорённость, которую можно нарушить
одной правкой конфигурации.

**Журнал диалога ведёт прокси, а не модель.** Артефакт `repowise-dialog.md`
рендерится из журнала обмена. Guard стадии на стороне агента умеет проверить
только существование файла и его размер — отличить полный транскрипт от
правдоподобного пересказа ему не с чем. Журнал делает полноту свойством
построения. Он же решает вопрос для агента разработки, у которого хуков нет
вовсе.

**Недоступность сервиса деградирует стадию, а не конвейер.** Агент, не
достучавшийся до индекса, пишет артефакт с исходом «источник недоступен» и идёт
дальше. Сервис не становится обязательной зависимостью пути, который до него
остановить было нечему.

## Известные ограничения

- **Семантического поиска нет без отдельного ключа эмбеддера.** У z.ai
  эмбеддингов нет — проверено спайком, вызовы отвергаются с `Unknown Model`
  (код 1211). Полнотекстовый поиск, граф, история, риск и мёртвый код работают
  в полном объёме. Подробности — [runbook.md](runbook.md).
- **Версия пакета пинуется точно** (`0.44.0` и не ниже): в `0.36.0` у
  `repowise mcp` нет флага `--host`, и эндпоинт недостижим по сети.
- **Выкладка в контур производства** — отдельная задача: первичная индексация
  требует памяти, которой на текущем сервере нет.
