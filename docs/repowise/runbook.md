# Разбор отказов

## Индекс отстал

**Как выглядит:** агент отвечает про код, которого в основной ветке нет. В
шапке артефакта диалога возраст индекса больше двух интервалов синхронизации.

```bash
curl -s -H "Authorization: Bearer $REPOWISE_AGENT_TOKEN" \
  http://localhost:7400/index-age | jq '.stale'
docker compose logs --tail 100 indexer
```

| В логе | Причина | Что делать |
|---|---|---|
| `fetch не удался` | токен протух либо нет доступа к репозиторию | обновить `REPOWISE_GIT_TOKEN` |
| `цикл не удался` | отказ обновления одного workspace | смотреть текст ошибки; цикл продолжается сам |
| ничего свежего | контейнер не работает | `docker compose up -d indexer` |
| цикл не укладывается в интервал | репозиториев стало больше | поднять `REPOWISE_SYNC_INTERVAL` либо развести workspace по расписаниям |

Догнать вручную:

```bash
docker compose exec indexer python /app/indexer.py sync-once
```

**Почему это важнее, чем кажется.** Молчащий индексатор хуже отставшего
индекса: отставание видно по возрасту, остановка — нет. Поэтому отказ по одному
workspace цикл не останавливает, а пишет в лог и идёт дальше.

## Прокси не отвечает

**Как выглядит:** стадия `repowise` деградирует, артефакт с исходом
`source-unavailable`, конвейер идёт дальше. Это штатное поведение, а не авария —
но причину найти надо.

```bash
curl -fsS http://localhost:7400/health
docker compose ps repowise-proxy
docker compose logs --tail 50 repowise-proxy
```

| Симптом | Причина | Что делать |
|---|---|---|
| `503` на `/mcp` | `REPOWISE_AGENT_TOKEN` пуст в конфигурации прокси | задать; пустой токен закрывает вход намеренно |
| `401` при верном токене | токены сервиса и агента разошлись | сверить обе стороны |
| `400 неизвестный workspace` | опечатка либо workspace не поднят | `docker compose ps` |
| `502 эндпоинт недоступен` | MCP-контейнер лежит | логи `repowise-*-mcp` |
| со стороны воркера недоступен, снаружи доступен | контур не в сети `poh-repowise-net` | подключить сервисы харнесса к сети |

Проверка со стороны контура:

```bash
docker compose exec issue-worker \
  python -c "from shared import repowise; print(repowise.available())"
```

## MCP-эндпоинт поднялся, но недостижим

Классический случай, стоивший спайка: **`repowise mcp` по умолчанию слушает
`127.0.0.1`**. Контейнер выглядит исправным, лог показывает `Uvicorn running`, а
соединения не устанавливаются.

```bash
docker compose logs repowise-contour-mcp | grep 'Uvicorn running'
```

`http://127.0.0.1:7338` — потерян флаг `--host 0.0.0.0` в `command`.
`http://0.0.0.0:7338` — привязка верная, искать причину в сети.

В версии `0.36.0` флага `--host` **нет вовсе**: если образ собрался со старой
версией, эндпоинт недостижим принципиально. Проверить:

```bash
docker compose exec repowise-contour-mcp repowise --version   # ждём 0.44.0+
```

## Админка не пускает при верном пароле

Почти всегда — **доллары в bcrypt-хэше не удвоены**. `docker compose`
интерполирует значения env-файла, и хэш доезжает обрезанным.

```bash
docker compose exec caddy sh -c 'echo -n "$REPOWISE_WEB_PASSWORD_HASH" | wc -c'
```

60 — норма. Меньше — удвоить `$` в файле учётки и перезапустить caddy.

Вход не поднимается вовсе — переменные учётки не заданы. Это намеренно: молча
открытая админка хуже упавшего входа.

## Админка отвечает 403

Не про basic_auth, а про **собственный guard пакета**: при привязке к
не-loopback адресу `repowise serve` требует `REPOWISE_API_KEY`.

```
{"detail":"Server is reachable from the network but REPOWISE_API_KEY is not set."}
```

Задать `REPOWISE_API_KEY` в `.env` и перезапустить `repowise-web`.

## Семантический поиск не работает

**Ожидаемо без отдельного ключа эмбеддера.** У z.ai эмбеддингов нет: вызовы
отвергаются с `Unknown Model` (код 1211), векторный индекс остаётся пустым.

```bash
docker compose logs indexer | grep -i 'embed'
```

`failed to embed … Unknown Model` — эмбеддер указывает на провайдера без
эмбеддингов. `REPOWISE_EMBEDDER не задан` — режим осознанный.

Что работает без эмбеддера: полнотекстовый поиск, граф символов, история и
blame, оценка риска правки, мёртвый код, страницы вики. Не работает: поиск по
смыслу.

Варианты: отдельный ключ провайдера с эмбеддингами (`openai`, `gemini`,
`openrouter`) либо `ollama` рядом — он не требует ключа.

## Индекс распух, поиск возвращает дубли

Проверить исключения — почти всегда это рабочие копии внутри репозитория:

```bash
docker compose exec repowise-contour-mcp \
  sh -c 'du -sh /workspaces/contour/* | sort -h | tail -5'
```

`poh-issue-agents` кратно больше остальных — в индекс попал
`.claude/worktrees/`. Правило R8 в [workspaces.md](workspaces.md); после
исправления пересобрать индекс репозитория заново.

## В индексе нашёлся секрет

```bash
docker compose exec repowise-contour-mcp repowise search "ZAI_API_KEY" --limit 5
```

Нашлось — считать ключ скомпрометированным и **сначала перевыпустить его**,
потом чистить: ключ уже размазан по страницам вики и векторному индексу, и
выборочно оттуда он не вынимается.

```bash
docker compose down
docker volume rm repowise_workspaces
docker compose run --rm indexer python /app/indexer.py bootstrap
```

Правило R9 удаляет `.env`, `*.pem` и `secrets/` из рабочих копий до
индексации — если секрет попал, значит он лежал под другим именем; дополнить
`SECRET_GLOBS` в `indexer/indexer.py`.

## Стоимость генерации

Проза страниц — единственная статья расходов сервиса; индексация, поиск и MCP
модель не зовут.

```bash
docker compose exec repowise-contour-mcp repowise costs
```

Дорого — не запускать `generate` вовсе: структурный индекс работоспособен сам
по себе, и на нём же построены граф, история и риск.

## Всё сразу перестало работать

Порядок проверки — снизу вверх, каждый шаг дешевле следующего:

```bash
docker compose ps                       # 1. контейнеры живы?
docker system df                        # 2. диск не кончился?
free -m                                 # 3. память?
docker compose logs --tail 30 indexer   # 4. индексатор?
curl -fsS localhost:7400/health         # 5. прокси?
```

Контур при этом продолжает работать: стадия деградирует, артефакты создаются,
аналитика идёт без дополнительного контекста. Это и было целью модификации M1
вердикта дебатов — сервис не на критическом пути.
