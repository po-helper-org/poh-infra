# init молча не делает ничего на каталоге с одним репозиторием

## Ситуация

Workspace `contour` из девяти репозиториев встал сразу, а `product` из одного — молча не встал никак. Симптом: эндпоинт поднимается, пишет `No .repowise directory found` и на каждый вопрос отвечает «индекса нет»; прокси исправно журналирует эти ответы как ходы диалога. Артефакт создаётся, выглядит настоящим, внутри — отказ.

## Причина

`repowise init` на каталоге, который не является ни git-репозиторием, ни мультирепо-корнем, выходит с кодом ноль, не сделав ничего. Классический молчаливый no-op: код успеха есть, результата нет.

## Решение

- Различаются два случая: два репозитория и больше — `init` на корне (workspace и два дополнительных инструмента); один — `init` внутри самого репозитория, workspace не создаётся вовсе.
- Путь до эндпоинта перестал быть одинаковым, compose его не вычислит — индексатор записывает его в файл `.mcp-path`.
- Guard после индексации: обязан появиться либо workspace в корне, либо `.repowise` в первичном репозитории; нет ни того ни другого — громкая ошибка вместо сервиса, отвечающего «индекса нет» на всё.
- Заглушки тестов приведены к поведению настоящего `init` — иначе тест проверял бы guard, а не то, ради чего написан.

## Как проверить

44 теста. Поднять workspace из одного репозитория: guard либо пропускает настоящий `.repowise`, либо падает с внятной ошибкой — «тихого» варианта больше нет.

## Уроки

У чужого CLI код выхода ничего не гарантирует: обёртка обязана проверять пост-условие (появился ли факт результата), а не доверяться нулю. Прогон «на одном репозитории» ловит не всё — см. кейс о первом запуске сервиса.
